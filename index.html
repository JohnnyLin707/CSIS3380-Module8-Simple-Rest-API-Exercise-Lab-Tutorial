1-6 拿连接串，并把数据库名改成 UserList（关键一步）

  1. 左侧 Database → 点你的集群（如 Cluster0）→ 右上 Connect。
  2. 弹窗里选 Drivers → 选 Node.js → Driver Version 选 6.0 or later → 点 Copy 复制连接串。
  3. 复制出来的东西长这样（先看懂每一段再改）：
Atlas 给你的原始串（示意）
mongodb+srv://johnny3380:YOUR_PASSWORD@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority
片段含义你要做的
mongodb+srv://协议头，表示连 Atlas 集群保留
johnny33801-4 建的用户名换成你自己的
YOUR_PASSWORD1-4 的密码换成你自己的；有特殊字符要编码（见下表）
cluster0.abcde.mongodb.net集群地址用 Atlas 给你的，别手打
mongodb.net/后面数据库名插入 UserList！原始串这里是空的（net/?retry）
?retryWrites=true&w=majority写入参数保留，& 是参数分隔符

改完后的最终版（存进记事本，第 3 节要粘到 .env）：

最终连接串模板
mongodb+srv://johnny3380:YOUR_PASSWORD@cluster0.abcde.mongodb.net/UserList?retryWrites=true&w=majority
两个必查点
① mongodb.net/ 后面必须是 UserList。如果留空或写成 test，Mongoose 会把数据写进别的库，你在 Atlas 里找不到 UserList，Postman 也一直返回空数组。
② 密码里有特殊字符时要做 URL 编码：@ → %40，: → %3A，/ → %2F，# → %23，? → %3F。最省事的办法就是 1-4 里说的——设密码时只用字母数字。

4写 Model：models/User.js（5 分钟）

题目写的三个字段：id: number, unique, required、email: text, required、username: text。Mongoose 没有 text 类型，一律用 String。unique: true 要自己加（老师书本例子里没有）。
models/User.js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema(
  {
    id: { type: Number, required: true, unique: true },
    email: { type: String, required: true, trim: true },
    username: { type: String, trim: true }
  },
  { timestamps: true }
);

module.exports = mongoose.model('User', userSchema);

mongoose.model('User', ...) 会让 Mongoose 自动使用 users 集合，符合题目。Mongoose 自己还会加一个 _id，不用管它，我们业务上用自定义的 id。

5写路由：routes/users.js（20 分钟）

和老师的书例子最大的不同：老师用 findById() 查默认的 _id；本题要按业务字段 id（数字）查，所以全部换成 findOne({ id }) / findOneAndUpdate / findOneAndDelete。另外题目的路径很特殊（/newuser、/modify/:id），不能照搬老师统一的 /:id。
routes/users.js — 完整代码
const express = require('express');
const User = require('../models/User');

const router = express.Router();

// 把 :id 转成数字；非法值直接 400，避免 CastError
function parseId(req, res, next) {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) {
    return res.status(400).json({ error: { message: 'id must be a number.' } });
  }
  req.userId = id;
  next();
}

// Task 3-a: GET /api/users  取全部
router.get('/', async (req, res, next) => {
  try {
    const users = await User.find().sort({ id: 1 });
    res.json(users);
  } catch (err) {
    next(err);
  }
});

// Task 3-b: GET /api/users/user/:id  取单个（题目里 repositories 是复制残留，就是取该用户）
router.get('/user/:id', parseId, async (req, res, next) => {
  try {
    const user = await User.findOne({ id: req.userId });
    if (!user) return res.status(404).json({ error: { message: 'User not found.' } });
    res.json(user);
  } catch (err) {
    next(err);
  }
});

// Task 5 (optional): GET /api/users/random
// ★ 必须放在 /user/:id 之前，否则 'random' 会被当成 :id 吃掉
router.get('/random', async (req, res, next) => {
  try {
    const count = await User.countDocuments();
    if (count === 0) return res.status(404).json({ error: { message: 'No users yet.' } });
    const skip = Math.floor(Math.random() * count);
    const user = await User.findOne().skip(skip);
    res.json(user);
  } catch (err) {
    next(err);
  }
});

// Task 3-c: POST /api/users/newuser  新建
router.post('/newuser', async (req, res, next) => {
  try {
    const { id, email, username } = req.body;
    if (id === undefined || !email) {
      return res.status(400).json({ error: { message: 'id and email are required.' } });
    }
    const user = await User.create({ id: Number(id), email, username });
    res.status(201).json(user);
  } catch (err) {
    next(err);
  }
});

// Task 3-d: PUT /api/users/modify/:id  只改 username
router.put('/modify/:id', parseId, async (req, res, next) => {
  try {
    const { username } = req.body;
    if (!username) {
      return res.status(400).json({ error: { message: 'username is required.' } });
    }
    const user = await User.findOneAndUpdate(
      { id: req.userId },
      { username },
      { new: true, runValidators: true }
    );
    if (!user) return res.status(404).json({ error: { message: 'User not found.' } });
    res.json(user);
  } catch (err) {
    next(err);
  }
});

// Task 3-e: DELETE /api/users/delete/:id
// 题目原文写的是 /user/delete/:id（少了 api），server.js 里两个都挂了
router.delete('/delete/:id', parseId, async (req, res, next) => {
  try {
    const user = await User.findOneAndDelete({ id: req.userId });
    if (!user) return res.status(404).json({ error: { message: 'User not found.' } });
    res.status(204).end();
  } catch (err) {
    next(err);
  }
});

module.exports = router;
为什么每条路由都要 try/catch + next(err)？ 这是老师 quote-api-checkpoints/final/app.js 的标准写法。异步路由里抛错 Express 5 虽然能自己接住，但显式 next(err) 更稳，而且统一走到最后的错误处理器，返回格式一致。
✅ 过关：五个端点 + random 都在，router.get('/random') 在 router.get('/user/:id') 前面。

// 统一错误处理器：四个参数，放最后
app.use((err, req, res, next) => {
  if (err.code === 11000) {
    return res.status(400).json({ error: { message: 'Duplicate id: id must be unique.' } });
  }
  if (err.name === 'ValidationError') {
    return res.status(400).json({ error: { message: err.message } });
  }
  res.status(err.status || 500).json({ error: { message: err.message } });
});

// 先连 MongoDB，成功后再监听端口
async function start() {
  try {
    await mongoose.connect(process.env.MONGODB_URI);
    console.log('Connected to MongoDB');
    app.listen(port, () => {
      console.log(`UserList API listening on http://localhost:${port}`);
    });
  } catch (err) {
    console.error('Could not connect to MongoDB:', err.message);
    process.exit(1);
  }
}

start();
